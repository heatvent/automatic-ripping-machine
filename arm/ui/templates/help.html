What ARM Does

Automatic Ripping Machine watches the optical drive. Insert a disc and it classifies it (Blu-ray, DVD, audio CD, or data), rips it, and files the result under your completed path so Plex, Jellyfin, or Emby can pick it up.

Typical Workflow

  1. Insert a disc. The tray is claimed and a job appears on Home.
  2. On an auto-mode drive, ripping starts immediately. Manual-mode drives wait until you confirm.
  3. Video discs are identified (title, year, type) using your metadata provider (OMDb or TMDb).
  4. MakeMKV (or backup mode) rips the disc. If transcoding is enabled, HandBrake or FFmpeg runs after the rip.
  5. When this install has skip-transcode enabled, the MakeMKV output is the finished file and the tray is freed sooner.
  6. The disc ejects. Finished rips show as success or fail in History.

Pages

Home
Active rips. Abandon a stuck job, open its log, or pick a playlist title when a Blu-ray repeats the movie. Home also shows whether Raw / Transcode / Completed folders are writable.
History
Past rips in a table. Search, filter successful or failed rips, delete, or open a log. System logs that are not tied to a rip are listed at the bottom of the first page.
Settings
General (machine name, web server, permissions), System Information (software versions and live hardware stats), Disk Drives, Movie Ripper, CD Ripper for audio discs, Notifications (including Emby and Apprise), and UI refresh interval.
Profile
Click your username in the sidebar footer to change the password or log out.

Drives

Each drive can be auto or manual. Auto starts as soon as a disc is ready. Manual waits for input in the UI. A drive that is only transcoding (rip already finished) does not keep the tray locked, so you can insert the next disc.

If a title is wrong, use Title Search or Custom Title on the job details page. Those change the saved name and output folder; they do not restart MakeMKV if ripping has already started. Edit Settings on a job changes min/max length, rip method, and main-feature for that job only.

Notifications

ARM does not show pop-up toasts in the browser. Job events can still go to Apprise (Discord, email, ntfy, and others) from the Notifications tab in Settings.

When the UI Asks to Reload

Most settings apply as soon as you save. A banner appears only if the web process itself must restart — for example after changing login or the listen address. In-progress rips are not stopped. Saving UI Settings (refresh interval) only needs a page reload on Home.

Send Titles to the ARM DVD Database

Upstream ARM can upload DVD identifiers (CRC64, title, year, IMDb id, disc label) to a shared community database so other people can identify discs without OMDb. Nothing personal is sent. This install does not need that for ripping: identification already uses your OMDb/TMDb key. The page still exists at /send_movies if you want to contribute; you need an ARM API key in arm.yaml.
